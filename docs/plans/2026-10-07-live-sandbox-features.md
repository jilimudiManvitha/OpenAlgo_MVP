## Implemented behavior

- Portfolio follows the main Live/Analyze switch. `live` accounts and `paper` accounts are separate in account lists, holdings, dashboard, transaction history, all nine reports/CSV, asset edits and price imports/refresh. Existing account kinds are retained; no production migration/relabel occurred. Mode and broker query assertions reject stale pages. A new query cache and page subtree per user/broker/mode clears old data and forms.
- Watchlist category names are shared organization; their instruments are filtered by account mode. Deleting a category cannot delete instruments hidden in the other mode. Existing paper GTT management/import is only available in Sandbox.
- Portfolio Watchlists & orders now includes an explicit review/confirmation ticket for NSE/BSE stock/ETF CNC limit orders and single GTTs. The screen names the selected mode and broker. Live uses the authenticated broker; Sandbox dispatches directly to its simulator. No dispatch occurs on page reads, charge previews, mode changes or broker changes.
- Native Live GTT availability follows installed adapters. This checkout has FYERS, Zerodha, Dhan, Angel and Upstox adapters (the older integration skill's two-broker list is stale). Unsupported brokers show unavailable. No synthetic Live GTT monitor was introduced. Regular orders use existing broker adapters. Semi-Auto accounts must use the existing Action Center rather than this direct ticket.
- Additive `investment_executions` stores owner, broker, mode, asset, payload, stable request key and outcome **before dispatch**. Reusing a key returns its recorded outcome; changed payloads conflict. Unknown/time-out outcomes are not resubmitted. Instruments with execution history cannot change identity or be deleted. Order history is bounded to 10,000 intents per owner and 1,000 displayed rows.
- Order review estimates brokerage/taxes with the logged-in broker's verified standard retail profile. The ledger's Record transaction dialog can explicitly **Apply broker charge estimate** for one delivery order at its actual price/date; actual charges can still be entered manually. Estimated notes carry broker/version, and changing trade inputs requires re-estimation before saving.
- Existing Sandbox GTT sync now adds estimated charges only to **newly imported fills**. Previously imported transactions and nonzero recorded fees are preserved. Legacy paper links lack broker provenance, so notes explicitly record the current-login-broker assumption. Unavailable estimates are surfaced in sync errors.
- Strategy Reports defaults to PAPER in Analyze/Sandbox and LIVE in Live mode, resetting filters/detail on identity or mode changes. Manual historical scenario selection remains available. The existing combined metrics, stock grouping, FY calendar, streaks and fee basis selector work for both scenarios.
- Reports additionally read confirmed Strategy Builder fills from mode-labelled `sm_strategy_run` / `sm_strategy_order`, owner-scoped via `sm_strategy`. Broker provenance comes from the run, not the later login. Read-only SQLite access, no new broker calls, report DB writes, strategy changes or background worker. FIFO matching stays within run/leg/position/instrument; incomplete/unprovable matches fail rather than guessing. Pending/unfilled quantities are excluded. Live/PAPER are separate. The adapter includes pre-year entries for carried basis, caps the selected execution history at 20,000 orders, and closes SQLite connections.
- Screener already reads authenticated broker market data in both modes. Its UI now identifies the selected mode and explains that market data stays live in both. It remains a read-only scanner; no strategy was converted to Live.

## Explicit limits

- Live broker network/order acceptance has **not** been tested with real transactions. All dispatch tests and the browser acceptance use fake broker boundaries. Real order/GTT capability also depends on the broker account, enabled instruments and session.
- New regular/native-GTT tickets record request outcomes, not automatic portfolio accounting. The user checks the existing Orderbook/GTT manager and records confirmed fills in the ledger; existing paper GTTs retain their dedicated automatic fill reconciliation. No unconfirmed acknowledgement is turned into a holding. Broker account holdings are not silently imported or duplicated.
- Strategy Builder reports require persisted, attributable confirmed fills. The legacy strategy-position book lacks mode history and cannot safely reconstruct daily Live trades; arbitrary external/manual broker trades are not assigned to strategies. Scheduled strategies remain in their existing Sandbox configuration. New adapter counts matched FIFO portions, so a split exit can contribute multiple trade rows; prices/times are recorded cumulative fill averages/timestamps. No synthetic candles are generated.
- Strategy Builder derived detail includes the run's fill history; its daily summary only realizes exits on the selected day. Original-recorded-fees mode has no contract-note fees for that source, explicitly stated in its note; estimates are the default.
- Standard fee coverage remains the eight verified brokers and NSE equity/NFO segments in [the brokerage handoff](2026-10-07-report-brokerage.md). Unknown profiles/BSE full-tax estimates are unavailable, never substituted. Estimates exclude DP, settlement/exercise, account, financing and special-service fees. Existing paper fills/manual transactions are not retroactively rewritten.
- Peak capital is simultaneous entry notional, not broker margin. Calendar streaks reflect recorded closed-trade days in the selected FY.
